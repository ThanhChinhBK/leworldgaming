Project Implementation Plan: Evaluating LeWorldModel and State-Vector MBRL in the TeamFightingICE Environment
1. System Overview and Vision
The rise of Artificial Intelligence (AI) systems in simulations and video games is witnessing a powerful paradigm shift. We are moving past the era of rule-based search algorithms and model-free reinforcement learning towards a more revolutionary concept: World Models. These systems do not merely learn to optimize a blind reward function; they build an internal understanding of the physical laws, dynamics, and consequences of actions within their interactive environment. This report outlines a strategic, comprehensive, and in-depth implementation plan for a personal research project specifically designed to test this hypothesis.
The project is built on an asynchronous workflow model, where the core source code architecture and logic will be developed on weekends, while mid-week days are fully automated using background data gathering and training scripts. The core focus of the research is to cross-evaluate the planning efficiency and dynamic comprehension of two modern AI systems. The first system is a standard State Vector-based Model-Based Reinforcement Learning (MBRL) model. We will explore the foundational PETS (Probabilistic Ensembles with Trajectory Sampling) algorithm 1, alongside state-of-the-art modern alternatives like DreamerV3 and DC-MPC. The second system, representing the bleeding edge of current techniques, is the LeWorldModel (LeWM)—a Joint-Embedding Predictive Architecture (JEPA) developed by Yann LeCun's research group, capable of learning directly from raw screenshots without pixel reconstruction.2
The chosen testbed is the DareFightingICE (formerly TeamFightingICE) platform, a standardized 2D fighting game system for the Fighting Game AI Competition (FTGAIC).3 This platform poses strict real-time control challenges, where all inference and planning decisions must be completed within a single frame's limit, equivalent to 16.67 milliseconds, to meet the 60 FPS standard.4 This massive computational workload—from environment simulation, forward propagation, and backpropagation, to action planning—is entirely constrained by a single hardware device: an NVIDIA GeForce RTX 3080 with 10GB of VRAM. Therefore, this report not only analyzes deep learning theories but also outlines a sharp software engineering strategy to optimize memory, accelerate hardware processing, and establish a continuous integration (CI) pipeline for machine learning tasks.
2. DareFightingICE Environment Specifications
To deploy a successful world model, a deep understanding of the interactive environment is a prerequisite. DareFightingICE is not just a standard fighting game; it is a complex simulator built in Java, providing a direct interface for AI agents to connect, extract states, and intervene in the character's decision-making engine.
DareFightingICE operates on a Client-Server Architecture. The core game engine runs on the Java Virtual Machine (JVM), while the AI algorithms are written in Python. The bridge between these two ecosystems is the pyftg library, a gateway interface utilizing socket-based message passing (typically on port 31415).5 This separation offers language independence but inevitably introduces a network latency overhead, requiring strict asynchronous programming (asyncio) to ensure data transfer doesn't throttle the neural network's inference speed.
Mechanically, each match runs for a fixed duration with the framerate hard-locked at 60 FPS. Every second equates to 60 decision cycles. The AI agent possesses two modes of observation, representing the two research branches of this project. The first is Pixel-based Observation (ScreenData), continuously extracting RGB image matrices that reflect exactly what a human player sees, including character poses, hitboxes, and projectiles. The second is a State Vector observation (FrameData), providing pre-extracted quantitative metrics such as 2D character coordinates, current HP, energy, and attack startup frames.
For automated machine learning projects, DareFightingICE provides critical command-line parameters. The --headless-mode flag disables the GUI entirely, freeing up precious CPU and VRAM resources.6 The --input-sync flag forces the game engine to wait until it receives action commands from both AIs before calculating the next frame.6 Combining these two parameters creates a perfect ecosystem for automated mid-week data collection scripts. Running in the background, the game can be accelerated far beyond real-time speeds, gathering tens of thousands of matches overnight to populate the Replay Buffer for deep learning models. Furthermore, running this platform via Docker containers will guarantee system consistency.7
3. Hardware Constraints: VRAM Budgeting on RTX 3080 10GB
The choice of model architecture and algorithm design for this project is entirely dictated by the single computing device available: the NVIDIA GeForce RTX 3080 10GB VRAM edition. Built on the Ampere architecture, this device offers immense floating-point computational power with 8704 CUDA cores and a 320-bit GDDR6X memory bus, delivering extreme matrix multiplication performance. However, the 10GB limit poses a severe optimization hurdle. Diffusion-based world models or vision-integrated Large Language Models (LLMs) exceed this capacity just loading weights, not to mention gradient storage during training.
To ensure the system can simultaneously train and run inference on the same device, a micro-VRAM allocation strategy must be established.

To achieve ultra-low latency (under 16.67 ms) at 60 FPS, hardware-level optimization is mandatory. First, Automatic Mixed Precision (AMP) will be activated via torch.cuda.amp.autocast. This technique casts weights and activations to FP16 or BFloat16 formats during matrix multiplications, maximizing the 3rd-gen Tensor Cores on the RTX 3080. This halves the memory bandwidth requirement and doubles computation speed.
Second, kernel launch overhead latency in PyTorch is a major roadblock for micro-inference operations. In environments requiring parallel trajectory calculations like PETS and LeWM, torch.compile (introduced in PyTorch 2.0) will be deployed. It analyzes the dynamic compute graph, fuses kernels, and generates optimized code via the Triton compiler. This intervention can easily push the inference time of compact models like LeWM down below the 10 ms mark, leaving ample time for network socket transmission.
4. Open-Source Baselines Analysis
A novel AI architecture cannot prove its superiority without solid benchmarks. The TeamFightingICE ecosystem, refined through years of FTGAIC tournaments, provides a treasure trove of open-source top-tier combat agents. To maximize weekend development efficiency, instead of re-implementing algorithms from scratch, these available open-source bots will be integrated as benchmark opponents and data-generation engines.
First is Thunder Bot, the 2018 tournament champion, representing the pinnacle of Monte Carlo Tree Search (MCTS) decision-making. Thunder maintains a hand-coded forward simulation model that perfectly mimics the game's physical rules. From the current state, it iterates through thousands of future action combinations to find the sequence yielding the highest HP differential. The existence of Thunder acts as an "upper bound" for planning capabilities that a deep learning system must beat.
Second is ERHEA_PI, the 2020 champion, utilizing a Rolling-Horizon Evolution Algorithm (RHEA).8 Instead of building a tree like MCTS, ERHEA_PI maintains a population of candidate action sequences, mutating and crossing them over through micro-generations within the 16ms window.8 ERHEA_PI's characteristics share a deep methodological similarity with the Trajectory Sampling optimization used in MBRL, making it a direct methodological counterbalance.
Additionally, basic baselines provided by the organizers, such as KickAI (static kicking) and BlindAI, will play an essential role in the early stages of the data pipeline. When the automated data collection kicks off on Monday, these random or rule-based agents will spar continuously, creating a vast phase space of collision, movement, and defensive states, forming an abundant training database for the self-supervised world models.
5. State-Based Architecture: Expanding from PETS to Modern MBRL
The first core evaluation branch of the project is deploying a Model-Based Reinforcement Learning (MBRL) model leveraging the game's pre-extracted State Vectors. The original plan focused on the PETS algorithm, but the landscape of MBRL has evolved, necessitating an exploration of more robust and appropriate models for fighting games.
5.1 The Foundational Baseline: PETS
PETS (Probabilistic Ensembles with Trajectory Sampling) was a breakthrough in addressing the sample inefficiency of model-free RL.1 By attempting to learn the environment's rules rather than just how to play, it requires exponentially less data. PETS overcomes the overfitting issues of deterministic neural networks by architecturalizing two concepts:
Aleatoric Uncertainty: The network outputs the parameters of a probability distribution (mean  and covariance ) instead of a static next state, capturing inherent environmental noise.
Epistemic Uncertainty: By maintaining an ensemble of multiple distinct neural networks initialized differently, the model can quantify its own lack of knowledge in unexplored state regions.
Action planning in PETS relies on the Cross-Entropy Method (CEM), sampling random action sequences and propagating them through the ensemble to evaluate future HP differentials. While historically significant, pure PETS struggles with the highly discrete action spaces found in fighting games (button presses rather than continuous motor torques).
5.2 The Modern Benchmark: DreamerV3
To push the state-vector baseline to the absolute limit, DreamerV3 will be evaluated as the primary modern alternative. Unlike many continuous-control-focused MBRL models, DreamerV3 is uniquely suited for this project because it natively excels in domains with discrete actions (like Atari or Minecraft).
DreamerV3 builds a Recurrent State Space Model (RSSM) that infers a compact latent state from the input vectors (or pixels). It then imagines thousands of future trajectories purely in the latent space to train an Actor-Critic policy, circumventing the need to plan online via CEM during the tight 16.67ms inference window. Furthermore, DreamerV3 is renowned for its robust, out-of-the-box performance without requiring extensive hyperparameter tuning across different environments.
5.3 Bridging Continuous and Discrete Spaces: TD-MPC2 & DC-MPC
Another highly potent candidate is TD-MPC2 (Temporal Difference Learning for Model Predictive Control). TD-MPC2 is exceptionally scalable and achieves state-of-the-art results in state-based continuous control tasks. However, extending TD-MPC2 to discrete action spaces is a known open problem, as its underlying planning relies on continuous MPC formulations.
To solve this, we will also consider the latest iteration, DC-MPC (Discrete Codebook Model Predictive Control). DC-MPC proves that modeling a discrete latent space using discrete codebook encodings (rather than continuous latent states) is highly effective. It performs competitively against both TD-MPC2 and DreamerV3, making it an excellent theoretical bridge to handle the discrete button-mash nature of DareFightingICE.
By utilizing frameworks like mbrl-lib or community implementations of DreamerV3 and DC-MPC, the weekend development phases can rapidly swap out the dynamics model engine while keeping the DareFightingICE environment wrapper intact.
6. Semantic Representation Learning: LeWorldModel (LeWM)
While state-vector models rely on human-engineered variables, the ultimate goal of AI is acting through raw observation. This is where the LeWorldModel (LeWM) shines. Based on the Joint-Embedding Predictive Architecture (JEPA) philosophy pioneered by Yann LeCun, LeWM entirely eliminates the need for pixel-level reconstruction.
Previous image-based world models (Generative methods) were forced to maintain massive decoders to recreate the next screenshot from latent representations. This process drains the 10GB VRAM and wastes compute on meaningless semantic details (like a moving cloud background) instead of focusing on the opponent's posture.
LeWM breaks through this by stabilizing end-to-end training directly from raw pixels by predicting entirely in the latent space. A DareFightingICE screenshot  passes through an Encoder to create a semantic representation vector . The Predictor takes  and the action , then directly predicts the next state's latent vector .2
The greatest challenge in Joint-Embedding architectures is "representation collapse," where the encoder ignores the input and outputs a constant vector, artificially dropping the loss to 0. LeWM solves this elegantly without complex moving averages. It utilizes only two loss terms: a next-embedding prediction loss, and a regularization term called SIGReg. SIGReg forces the latent vectors to scatter according to a Gaussian distribution, strictly maintaining latent space diversity and preventing collapse.2
This ultra-lightweight architecture, containing roughly 15 million parameters, fits comfortably within an RTX 3080.2 Training on a single GPU takes mere hours. More importantly, during real-time combat inference, LeWM can plan in the latent space up to 48x faster than massive foundation-model-based world models.10 By stripping away the heavy image decoder, LeWM can calculate hundreds of latent trajectories in parallel using small matrix multiplications, easily sustaining the 16.67ms frame budget.
7. Asynchronous Execution Pipeline
To ensure the feasibility of a complex personal research project with limited time, a strict software engineering pipeline must be applied, separating manual coding (weekends) from automated compute (mid-week).
7.1 Core Development Phase (Weekends)
Weekends are reserved for architectural thinking and system integration. The DareFightingICE open-source code, pyftg gateway, and algorithm repositories (like mbrl-lib or DreamerV3) will be connected. An OpenAI Gym-compatible wrapper will be developed to unify the interaction interface for all models (accepting Actions, returning States/Pixels/Rewards).
Simultaneously, the Probing modules for LeWM will be refined. Because LeWM predicts an abstract latent space  2, a small linear regression neural network will be added to map this vector to concrete physical parameters (like HP difference), allowing the planning algorithm to evaluate action branches. All debugging related to Out-of-Memory (OOM) errors or frame drops will be conducted manually using torch.profiler.
7.2 Background Compute Phase (Mid-Week)
Mid-week runs are fully automated via Bash and Python scripts (e.g., get_data_script.py and training_script.py), orchestrated by tools like tmux or systemd on a headless Linux environment.
Data Pipeline: A fleet of Docker containers running DareFightingICE with --headless-mode and --input-sync flags 6 will be instantiated. Random combatants (KickAI, BlindAI) and open-source expert systems (Thunder, ERHEA_PI) will fight continuously. The resulting data will be packaged into ultra-compressed binary formats like HDF5 or LMDB to maximize I/O speeds.
Training Pipeline: Python scripts will periodically read the latest data chunks from the drive to update weights. For the state-vector models (DreamerV3/PETS), they will fine-tune on the new experience buffer. For LeWM, self-supervised learning will run using the next-embedding loss and SIGReg.2 Checkpoints will be autosaved, allowing weekend research to pick up seamlessly.
8. Quantitative Evaluation Framework
The ultimate goal is not just getting models to run, but proving the conceptual superiority of World Models over traditional algorithms through systemic metrics. The final evaluation will involve an automated Round-Robin Tournament, pitting the MBRL state-vector models and LeWM directly against champions like Thunder (MCTS) and ERHEA_PI.
Core metrics include:
Win-Rate and HP Difference: The most direct measure of tactical efficiency. By calculating average damage dealt minus damage received, we objectively quantify the quality of the model's planned action sequences.
Uncertainty Calibration / Latent Probing: For ensemble models, we will track if prediction variance spikes in rare combat states, measuring robustness. For LeWM, we will track the R-squared accuracy of the probing linear layer predicting HP from latent embeddings to prove physical understanding.
Frame Drop Rate: The ultimate reality check for real-time feasibility. A micro-latency monitoring script will record how often inference exceeds 16.67 ms. LeWM’s 15M parameter structure promises near-zero frame drops on an RTX 3080, but this must be empirically compared against MCTS tree-traversal speeds in Java.
Comparing MCTS (requiring hard-coded game rules) with world models (self-learning rules via observation) provides deep insights. If a game patch unexpectedly alters attack speeds, an expert bot like Thunder instantly fails until a human rewrites its forward simulator. Meanwhile, DreamerV3 and LeWM merely need to absorb new data to adjust their internal weight matrices, demonstrating a biological adaptability that static systems lack.
9. Technical Risk Assessment and Mitigation
Applying cutting-edge models like JEPA and DreamerV3 to a harsh real-time platform like DareFightingICE on limited hardware carries risks.
First, VRAM Out-of-Memory (OOM) risks from image data. While LeWM weights are small (~60MB), the sheer volume of image tensors pushed across the PCIe bus can fill 10GB. The primary mitigation is down-sampling DareFightingICE's resolution to standard Vision Transformer grid sizes (e.g., 224x224), or converting to grayscale to save bandwidth and tensor space.
Second, Socket Latency Overhead. The pyftg library requires data transmission over a socket. OS-level CPU scheduling variations can spike transfer latency, eating into the 16.67ms neural network budget. To resolve this, the communication structure will be rewritten into an asyncio loop with a Buffer Queue. The inference model will constantly poll the freshest state from the queue rather than waiting for synchronous sends from the game engine.
Finally, Static Representation Collapse in LeWM. Fighting games have long frames where characters just stand and stare or loop idle animations. If training data is flooded with identical frames, the LeWM encoder might converge to a trivial solution. The mitigation includes strict weight control of the SIGReg parameter () 2 and forcing random agents during the mid-week pipeline to execute special attacks (like Hadoukens) at a high frequency to inject massive entropy into the dataset.
10. Conclusion
This personal research project implementation plan provides a detailed blueprint to test the power of modern deep learning models in real-time environments. By establishing an asynchronous workflow, bounded hardware like the 10GB NVIDIA RTX 3080 can be pushed past its conventional limits to provide 60 FPS inference while training mid-week. Pitting modern State-Vector MBRL (DreamerV3, DC-MPC) and raw-pixel Joint-Embedding architectures (LeWM) against exquisitely tuned search algorithms like Thunder promises a highly valuable empirical report. Beyond applying new tech, this project re-enacts computer science's deepest philosophy: granting a system the ability to construct its own mathematical model of the world, rather than imprisoning it in static simulation code written by humans.
